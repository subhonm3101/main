# Подключение панели владельца DoniШеф

Сайт остаётся статическим, а Supabase обеспечивает защищённый вход, базу данных и хранилище фотографий.

## 1. Создайте проект

Создайте проект в Supabase и откройте **SQL Editor**. Выполните весь файл [`supabase-schema.sql`](./supabase-schema.sql). Он создаёт каталог, заявки, снимки состава заказа, контакты ресторана, проверки доступа и хранилище `menu-photos`; также добавляет доступность блюд и поля согласия на обработку данных. Если проект уже настроен, выполните обновлённый файл повторно. Перед публикацией новой версии сайта сначала примените эту схему: новая RPC-процедура заказа требует параметры согласия и версии политики.

## 2. Создайте учётную запись владельца

В **Authentication → Users** добавьте владельца с email и паролем. В настройках Authentication отключите публичную регистрацию пользователей. Затем выполните в SQL Editor запрос, заменив email на адрес созданной учётной записи:

```sql
insert into public.admin_users (user_id)
select id
from auth.users
where email = 'owner@example.com'
on conflict (user_id) do nothing;
```

Только идентификаторы из `admin_users` получают доступ к заказам и редактированию меню и контактов. Не добавляйте в эту таблицу обычные клиентские учётные записи.

## 3. Подключите сайт

В **Project Settings → API** скопируйте Project URL и публичный ключ `anon` / `publishable`. Впишите их в `supabase-config.js`:

```js
window.DONISHEF_SUPABASE_CONFIG = {
  url: 'https://ВАШ-ПРОЕКТ.supabase.co',
  anonKey: 'ВАШ-ПУБЛИЧНЫЙ-КЛЮЧ'
};
```

Публичный ключ предназначен для браузера; доступ к данным контролируют SQL-политики. **Никогда не помещайте в этот файл `service_role` или secret key.**

Опубликуйте файлы сайта на HTTPS-хостинге. Затем откройте `/admin.html` и войдите под созданной учётной записью. В разделе **«Меню»** можно искать блюда, менять цены и данные, добавлять или удалять позиции, загружать фотографии, а также ставить отдельное блюдо на стоп и возвращать его в наличие кнопкой рядом с ним. Если таблица меню новая и пустая, добавьте позиции через кнопку **«Добавить блюдо»**.

## Какие данные видны в панели

- В заказах сохраняются заявки, оформленные через сайт, состав блюд, цены на момент заказа и контактные данные. Заказ сохраняется до перехода клиента в WhatsApp или MAX.
- В разделе «Контакты для звонков» владелец меняет телефон ресторана и номера WhatsApp и MAX. Телефон для звонков показывается на сайте; WhatsApp используется для открытия чата, а MAX — для отображения номера получателя скопированного сообщения. Номера хранятся в международном формате, например `+79191545232`.
- Номер WhatsApp используется сайтом для открытия чата. Для MAX сайт копирует текст заявки, а клиенту показывает сохранённый номер, который нужно найти в приложении.
- Запросы на бронирование отдельного зала пока продолжают отправляться в WhatsApp/MAX и в панели заказов не отображаются.
- Сайт не хранит данные банковских карт и не проводит оплату.
- В формах заказа и бронирования обязательно поставить отметку согласия; для заказов, сохраняемых в Supabase, сохраняются время согласия и версия политики. До публичного запуска заполните все поля в квадратных скобках на странице `privacy-policy.html`, проверьте фактические сроки и места хранения данных, условия Supabase/хостинга и контакт оператора. Не публикуйте страницу с незаполненными реквизитами.
- В проверенной версии не обнаружены счётчики веб-аналитики или рекламные пиксели. Корзина хранится в localStorage. Карта Яндекса загружается только после нажатия клиентом кнопки; Google Fonts удалён. Библиотека Supabase всё ещё запрашивается с jsDelivr, каталог и контакты загружаются с Supabase, а отправка формы может передавать заказ в Supabase. Перед сбором данных владелец должен подтвердить регион базы (для данных жителей РФ особенно проверить требование локализации), получателей/обработчиков, подать обязательное уведомление Роскомнадзору, если оно требуется для фактической модели, и проверить необходимость уведомления о трансграничной передаче.
- Страницы `privacy-policy.html`, `personal-data-consent.html`, `terms-of-use.html` и `cookie-policy.html` содержат пометки черновика и скрыты от индексации, пока владелец не заполнит и не утвердит сведения. Владелец должен подтвердить права/лицензии на каждое изображение и видео: наличие файла в проекте само по себе права не подтверждает.

Данные клиентов являются персональными. Ограничьте список владельцев и настройте срок хранения в соответствии с правилами обработки персональных данных ресторана. Технический чекбокс сам по себе не подтверждает полное соответствие сайта требованиям закона.
