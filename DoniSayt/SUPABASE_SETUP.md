# Подключение панели владельца DoniШеф

Сайт остаётся статическим, а Supabase обеспечивает защищённый вход, базу данных и хранилище фотографий.

## 1. Создайте проект

Создайте проект в Supabase и откройте **SQL Editor**. При первой настройке выполните файл [`supabase-schema.sql`](./supabase-schema.sql). Он создаёт каталог, заявки, снимки состава заказа, контакты ресторана, проверки доступа и хранилище `menu-photos`; также добавляет доступность блюд и поля согласия на обработку данных. Supabase — облачный сервис: его не нужно запускать вручную при каждом изменении сайта.

Схему базы выполняют один раз при первичной настройке. Повторно запускайте обновлённый SQL-файл только когда инструкция к изменению сайта прямо требует миграцию схемы. Обычные изменения меню (название, цена, наличие, фото) сохраняются через `/admin.html` и сразу записываются в базу — SQL Editor для них не нужен.

## 2. Создайте учётную запись владельца

В **Authentication → Users** добавьте владельца с email и паролем. В настройках Authentication отключите публичную регистрацию пользователей. Затем выполните в SQL Editor запрос, заменив email на адрес созданной учётной записи:

```sql
insert into public.admin_users (user_id)
select id
from auth.users
where email = 'owner@example.com'
on conflict (user_id) do nothing;
```

Только идентификаторы из `admin_users` получают доступ к заказам и редактированию меню и контактов. Не добавляйте в эту таблицу обычные клиентские учётные записи.

## 3. Подключите сайт

В **Project Settings → API** скопируйте Project URL и публичный ключ `anon` / `publishable`. Впишите их в `supabase-config.js`:

```js
window.DONISHEF_SUPABASE_CONFIG = {
  url: 'https://ВАШ-ПРОЕКТ.supabase.co',
  anonKey: 'ВАШ-ПУБЛИЧНЫЙ-КЛЮЧ'
};
```

Публичный ключ предназначен для браузера; доступ к данным контролируют SQL-политики. **Никогда не помещайте в этот файл `service_role` или secret key.**

Опубликуйте файлы сайта на HTTPS-хостинге. Затем откройте `/admin.html` и войдите под созданной учётной записью. В разделе **«Меню»** можно искать блюда, менять цены и данные, добавлять или удалять позиции, загружать фотографии, а также ставить отдельное блюдо на стоп и возвращать его в наличие кнопкой рядом с ним. Если таблица меню новая и пустая, добавьте позиции через кнопку **«Добавить блюдо»**.

## Какие данные видны в панели

- В заказах сохраняются заявки, оформленные через сайт, состав блюд, цены на момент заказа и контактные данные. Заказ сохраняется до перехода клиента в MAX.
- В разделе «Контакты для звонков» владелец меняет телефон ресторана и номер MAX. Телефон для звонков показывается на сайте; MAX-номер отображается клиенту после подготовки сообщения.
- Сайт копирует текст заказа или заявки и открывает MAX; пользователь самостоятельно выбирает чат и отправляет сообщение.
- Запросы на бронирование отдельного зала отправляются пользователем через MAX и в панели заказов не отображаются.
- Сайт не хранит данные банковских карт и не проводит оплату.
- В формах заказа и бронирования обязательно поставить отметку согласия; для заказов, сохраняемых в Supabase, сохраняются время согласия и версия политики. До публичного запуска проверьте фактические сроки и места хранения данных, условия Supabase/хостинга и контактные сведения оператора.
- Корзина хранится в localStorage. Карта Яндекса встроена в раздел контактов; адрес выбирается на карте, а не в форме заказа. Google Fonts удалён. Библиотека Supabase загружается с jsDelivr, каталог и контакты — из Supabase, а заказ сохраняется через Supabase. Перед сбором данных владелец должен подтвердить регион базы (для данных жителей РФ особенно проверить требование локализации), получателей/обработчиков, подать обязательное уведомление Роскомнадзору, если оно требуется для фактической модели, и проверить необходимость уведомления о трансграничной передаче.
- Страницы `privacy-policy.html`, `personal-data-consent.html`, `terms-of-use.html` и `cookie-policy.html` содержат пометки черновика и скрыты от индексации, пока владелец не заполнит и не утвердит сведения. Владелец должен подтвердить права/лицензии на каждое изображение и видео: наличие файла в проекте само по себе права не подтверждает.

Данные клиентов являются персональными. Ограничьте список владельцев и настройте срок хранения в соответствии с правилами обработки персональных данных ресторана. Технический чекбокс сам по себе не подтверждает полное соответствие сайта требованиям закона.

## Удаление заказов и клиентов

Чтобы кнопка «Удалить выбранных» работала, один раз выполните в Supabase → SQL Editor:

```sql
drop policy if exists "Admins delete orders" on public.orders;
create policy "Admins delete orders" on public.orders for delete to authenticated using (public.is_donishef_admin());
grant delete on public.orders to authenticated;
```
